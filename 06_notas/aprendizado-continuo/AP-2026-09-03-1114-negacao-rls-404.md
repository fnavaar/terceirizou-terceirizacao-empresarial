# AP-2026-09-03-1114 — Negação de RLS no PocketBase responde 404 (não 403) ao alterar de outro dono

- Status: candidato
- Escopo: projeto do cliente
- Task/SPEC: F2-T05 / SPEC-2-001 (CA-2-005)
- Sinal: ao tentar PATCH (alterar) um lead de outro responsável com usuário de papel comercial, a API respondeu HTTP 404 "resource not found" em vez de 403.
- Evidência: teste 5.3 da F2-T05 — comercial autenticado, PATCH em lead de "Henrique Tavano" → 404; GET do mesmo lead com o mesmo token também não o enxerga.
- Regra reutilizável: em PocketBase (Skip), quando uma updateRule/RLS nega, o registro é tratado como inexistente (404), não como "proibido" (403). Ao testar permissões, esperar 404 como negação válida e não marcar como falha; não confundir com registro ausente.
- Quando aplicar: testes de acesso por papel, RLS, frontend que trata erros de permissão.
- Quando não aplicar: rotas customizadas com $apis.requireAuth (essas devolvem 401/403 explícito).
- Confiança: alta — comportamento reproduzido com usuário de teste.
- Privacidade: sem segredo, dado pessoal ou conteúdo bruto.
